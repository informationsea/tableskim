# エクスポートと変換

[← 目次](README.md)

TableSkim は [編集モード](editing.md) の外では開いたファイルを変更しませんが、表示している内容を新しいファイルに書き出せます。表示内容は、保存していない編集を含めて書き出します。

| 機能                        | 対象                                 | 出力                      | 書き出す内容                            |
| --------------------------- | ------------------------------------ | ------------------------- | --------------------------------------- |
| Export View                 | すべてのシート（SQL の結果を含む）   | CSV、TSV、Excel、Parquet  | 表示どおりのシート：並べ替え・フィルタ適用後、非表示の列を除く |
| Convert to Parquet / DuckDB | CSV、TSV、VCF などのテキストファイル | Parquet、DuckDB           | ファイル全体をファイルの順序で          |
| 解析コード                  | ファイルのシート（SQL の結果を除く） | R、Python                 | ファイルを読み、フィルタ・グラフ・Group By を再現するコード |

## Export View

- GUI：**File → Export View...**（`Ctrl+Shift+E`）
- ターミナル UI：`w`
- Web アプリ：**Export**。ダイアログで形式を選ぶと、ブラウザのダウンロード先に保存されます。

ファイル名を指定すると、拡張子で形式が決まります。

| 拡張子           | 形式                                       |
| ---------------- | ------------------------------------------ |
| `.csv`           | カンマ区切りテキスト（UTF-8）              |
| `.tsv`、`.tab`   | タブ区切りテキスト（UTF-8）                |
| `.xlsx`          | Excel ブック                               |
| `.parquet`       | Parquet                                    |

これ以外の拡張子を指定すると、GUI ではファイルダイアログで選んだ種類の拡張子を付け、ターミナル UI では「Choose a name ending in .csv, .tsv, .xlsx or .parquet」と表示して受け付けません。

ファイル名の候補は、元のファイル名に `-export` を付けたもの（例：
`sales-export.csv`）です。複数のシートを持つファイルでは、
`book-Sheet1-export.xlsx` のようにシート名も入ります。

書き出す内容：

- **フィルタ** を通った行だけを、現在の **並べ替え** の順で書き出します。
- **非表示** の列以外のすべての列を書き出します。
- **CSV / TSV**：各セルを表示どおりに書き出し、必要な場合だけ引用符で囲みます。シートに列名があれば見出し行を付けます。
- **Excel / Parquet**：数値、真偽値、日付、時刻は型を保ちます。（CSV ファイルなどの）文字列の列は、すべての値が収まる最も狭い型になります。たとえば数値の文字列の列は数値の列に、ISO 形式の日付の列は日付の列になります。
  Parquet の列名は見出しに従い、見出しがなければ `A`、`B`、`C`… になります。

整数と小数が混在し、浮動小数点数への変換で整数の値が変わる列は、文字列として保存します。Convert to Parquet / DuckDB でも同じです。

エクスポートはバックグラウンドで実行され、進捗が表示されます。**Cancel**
（GUI）または `Esc`（TUI）で中止できます。保存先のファイルは書き出しが完了してから置き換えるので、中止しても既存のファイルはそのまま残ります。エクスポート中にシートの並べ替えやフィルタを変えるとエクスポートは失敗するので、もう一度実行してください。

## Convert to Parquet / DuckDB

GUI とターミナル UI では、保存していない変更がある場合は元のファイルを開いたままにします。変換したファイルは保存し、開きません。

テキストファイルには索引がないため、大きな CSV ファイルを並べ替えたりフィルタしたりするたびに全行をメモリに読み込みます。一度 Parquet か DuckDB
に変換しておくと、以降の作業が速くなります。これらの形式では並べ替えとフィルタを DuckDB の中で行い、[SQL](sql.md) でクエリすることもできます。

- GUI：**File → Convert to Parquet / DuckDB...**。保存先を指定すると、拡張子（`.parquet`、または `.duckdb` / `.ddb`）で形式が決まります。変換が終わると、変換したファイルを開きます。
- ターミナル UI：`P`（Parquet）または `D`（DuckDB）で、元のファイルと同じ場所に書き出し（例：`data.csv.gz` → `data.parquet` または `data.duckdb`）、そのファイルを開きます。
- Web アプリ：**Convert**。Parquet か DuckDB を選ぶと、元のファイル名にちなんだ名前でブラウザのダウンロード先に保存されます。

書き出す内容：

- ファイル全体をファイルの順序で書き出します。表示中の並べ替えとフィルタは適用 **されません**（適用したい場合は Export View を使います）。
- 現在の **見出し**、**`##` 行**、**文字コード** の設定を使うので、表示と同じ行と列になります。
- 各列は、すべての値が収まる最も狭い型（整数、小数、真偽値、日付、タイムスタンプ、文字列）になります。型付きの列では、空のセルは NULL になります。
- DuckDB ファイルには、元のファイル名にちなんだ名前のテーブルが 1 つ入ります。

エクスポートと同じく変換も中止でき、保存先のファイルは完成してから置き換えます。元のファイル自体を保存先に選ぶことはできません。

## R と Python の解析コード

TableSkim で行った解析を R や Python で再現するコードを書き出せます。スクリプトやノートブックの出発点として使えます。コードはファイルを読み、ビューのフィルタを適用してから、ヒストグラムや散布図を描くか、Group By を計算するか、（シートそのもののときは）行を並べ替えて非表示の列を除きます。

- GUI：ヒストグラムと散布図のウィンドウの **Save Code...**。**File → Export Analysis Code...** は現在のシートの、**Group By** シートではそれを作った Group By のコードを書き出します。ファイルダイアログで選んだ種類で言語が決まります。
- ターミナル UI：シート、ヒストグラム（`B`）、密度分布（`M`）で `K`。プロンプトにファイルと同じ場所のファイル名が表示され、`Tab` で言語を切り替えます。
- Web アプリ：ツールバーの **Code** と、グラフのダイアログの **Code…**。ダイアログにコードが表示され、**Copy** と **Save…** が使えます。コードはファイルを名前だけで読むので、`path` をファイルの場所に書き換えてください。

書き出す言語は 3 種類です。

| 言語                          | ライブラリ                                   | 名前の候補                 |
| ----------------------------- | -------------------------------------------- | -------------------------- |
| R (tidyverse)                 | readr、dplyr、ggplot2（ほかの形式では readxl、arrow、jsonlite、DBI） | `sales-histogram.R`        |
| Python (polars + plotnine)    | polars、plotnine（必要に応じて duckdb、fastexcel） | `sales-histogram-polars.py` |
| Python (pandas + matplotlib)  | pandas、matplotlib（必要に応じて duckdb、openpyxl） | `sales-histogram-pandas.py` |

たとえば `Age` が 40 より大きい行について、`Active` で積み上げた `Salary` のヒストグラムは、R では次のようになります。

```r
library(tidyverse)

path <- "/data/normal.csv"
df <- read_csv(path)

df <- df |>
  filter(Age > 40)

p <- ggplot(df, aes(x = Salary, fill = factor(Active))) +
  geom_histogram(bins = 30) +
  labs(y = "rows", fill = "Active")
print(p)
# ggsave("plot.png", p)
```

コードは厳密さよりも簡潔さを優先しています。

- ファイルは各ライブラリの規則で読みます。列の型はライブラリが推測し、readr は値の前後の空白を取り除きます。フィルタは、数値・日付・真偽値の列とはその型の値として比べ、それ以外の列とは文字列として比べます。
- R と polars では、空のセルとの比較は（「等しくない」を除いて）その行を除きます。TableSkim は空のセルを空の文字列として比べます。
- グラフの色、区間、軸は各ライブラリの既定のままです。X が文字列なら箱ひげ図に、文字列の列のヒストグラムは出現回数の多い値の棒グラフになります。
- Group By はグループごとの行数（`count`）を数え、列には TableSkim と同じ名前（`Salary sum` など）を付けます。文字列の列の合計・平均・標準偏差は省きます。

SQL の結果には読むファイルがないため、コードは書き出せません（それを集計した Group By も同様です）。
